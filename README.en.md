## 📖 User Guide

Complete guide (landing page + step-by-step instructions): **https://inematds.github.io/agentes-fronteiros/guia/en/**

A **migration** project for the INEMA ecosystem of specialized agents to
**one generalist agent + skills with contracts + reusable tools +
validation loop + living knowledge base**.

Three combined references:

| Reference | What’s included here |
|---|---|
| **Migration plan** (`PLANO.md`) | The 10 stages: inventory → base agent → skills → tools → progressive disclosure → learning → loop → contract → router → living system. |
| **eve (Vercel)** — folder model | The agent is a directory: `agent/instructions.md`, `skills/`, `tools/`, `connections/`, `channels/`, `schedules/`, `subagents/`, `hooks/`, `lib/`, `sandbox/` and `evals/` alongside it. Here, this is a **folder convention**, not the TypeScript runtime. |
| **OKF + LLM wiki (Karpathy)** | The knowledge base in `wiki/` is an OKF bundle: Markdown + YAML frontmatter (`type` required, `sources`, `generated`, `verified`, `status`, `stale_after`), with `index.md` and `log.md` reserved. The agent maintains the wiki: it ingests raw sources from `wiki/raw/`, consolidates them into concepts, and updates the index and log. |

## Structure

```text
agentes-fronteiros/
├── README.md · PLANO.md · ARQUITETURA.md · CLAUDE.md · FALHAS.md
├── agent/                 # eve layout (convention)
│   ├── agent.yaml         # model, effort, routing policy
│   ├── instructions.md    # always-on prompt for the generalist agent (INEMA AGENT)
│   ├── skills/            # migrated skills (SKILL.md + references/ + scripts/ + contrato.yaml)
│   ├── tools/             # reusable tools (ffmpeg, transcription, rendering, validation)
│   ├── connections/ channels/ schedules/ subagents/ hooks/ lib/ sandbox/
├── evals/                 # real tasks used to approve each migrated skill
├── wiki/                  # OKF bundle (knowledge base)
│   ├── SCHEMA.md          # wiki conventions (the LLM wiki "schema")
│   ├── index.md · log.md  # reserved (listing + history)
│   ├── raw/               # ingested raw sources (never edited)
│   ├── conceitos/         # curated concepts (okf, eve, llm-wiki, skill-contract, loop...)
│   ├── skills/            # 1 concept per existing skill (generated by tools/inventario.py)
│   ├── agentes/           # 1 concept per existing agent
│   └── clusters/          # detected overlaps (multiple skills, same intent)
├── migracao/
│   ├── template-contrato.yaml · template-SKILL.md
│   └── contratos/         # reels.yaml · video-explicativo.yaml · curso.yaml (pilots)
├── tools/
│   ├── inventario.py      # scans ~/.claude/skills and ~/.claude/agents → wiki/skills, wiki/agentes, wiki/clusters, index
│   └── wiki_lint.py       # validates OKF frontmatter (fails if `type` is missing), links, and reserved files
└── interface/
    ├── server.py          # local server (stdlib) — API for the wiki
    └── index.html         # migration interface (kanban by stage, clusters, contracts, wiki)
```

## Installation

Requirements: **Python 3.11+** and **PyYAML**. There is no build, database, or framework.

```bash
git clone https://github.com/inematds/agentes-fronteiros
cd agentes-fronteiros

# PyYAML (the only package outside the standard library)
pip install pyyaml            # or: sudo apt install python3-yaml

# check
python3 -c "import yaml; print('ok', yaml.__version__)"
```

The inventory reads the skills and agents installed in Claude Code on your machine:
`~/.claude/skills/*/SKILL.md` and `~/.claude/agents/*.md`. If they are elsewhere,
pass `--skills DIR --agents DIR` to `inventario.py`.

## How to use

### 1. Generate the inventory (stage 1 of the plan)

```bash
python3 tools/inventario.py
# skills: 116 (without SKILL.md: 1)  agents: 7  clusters: 16  changed files: N
```

Writes an OKF page for each skill in `wiki/skills/`, one for each agent in `wiki/agentes/`, and a
cluster for each group of skills competing for the same intent in `wiki/clusters/`. Regenerates the
`index.md` files and records one line in `wiki/log.md`. It is idempotent: running it again without changes
does not alter anything, and **preserves** the `migracao:` field and the "Migration Notes" section on each page.

Options: `--dry-run` (show only), `--skills DIR`, `--agents DIR`, `--wiki DIR`.

### 2. Validate the wiki

```bash
python3 tools/wiki_lint.py
# wiki: 149 concepts · 0 errors · 2 warnings
```

Fails (exit 1) if a concept lacks `type`, if `index.md`/`log.md` have concept frontmatter, if a relative link is broken, if `related` points to a nonexistent concept,
or if `status` or `migracao.estagio` is not in the list. Run before every commit.

### 3. Open the migration interface

```bash
python3 interface/server.py            # http://127.0.0.1:8765
python3 interface/server.py --port 9000 --host 0.0.0.0   # another port / local network
```

Tabs:

| Tab | What it does |
|---|---|
| **Kanban** | Skills and agents in columns by stage. Click a card to open the drawer. |
| **Table** | Filterable list (search, cluster, type) with triggers, cited tools, and number of scripts. |
| **Clusters** | Overlap groups with a progress bar and a link to the cluster page. |
| **Contracts** | The YAML files in `migracao/contratos/` (trigger, acceptance, complete YAML). |
| **Wiki** | Reader for any concept by ID (e.g., `conceitos/okf`), with navigable links. |
| **Log** | The `wiki/log.md` file. |
| **↻ Re-inventory** | Runs `tools/inventario.py` and reloads. |

In the drawer, you can change **stage**, **cluster**, **destination** (name of the migrated skill), and **notes**.
"Save" writes directly to the page frontmatter in `wiki/skills/<nome>.md` and adds a
line to `wiki/log.md`. The chips at the top filter by stage.

The interface only works while the local server is running (the API reads and writes files); opened
as a static page, it displays the command to start the server.

API (for scripts): `GET /api/inventario`, `GET /api/clusters`, `GET /api/contratos`,
`GET /api/wiki?id=<conceito>`, `GET /api/log`, `POST /api/migracao {id, estagio, cluster,
destino, notas}`, `POST /api/rescan`.

### 4. Migrate a skill (the plan cycle)

For each skill, in kanban stage order:

1. **mapped** — complete the page's "Map" table in `wiki/skills/<nome>.md` (output and validation) and write the contract:
   ```bash
   cp migracao/template-contrato.yaml migracao/contratos/<nome>.yaml   # edit
   ```
2. **skill** — create the migrated skill from the template:
   ```bash
   mkdir -p agent/skills/<nome>/references
   cp migracao/template-SKILL.md       agent/skills/<nome>/SKILL.md     # edit
   cp migracao/contratos/<nome>.yaml   agent/skills/<nome>/contrato.yaml
   ```
3. **tools** — move repeated code (ffmpeg, transcription, download, rendering, validation) to `agent/tools/<x>.py` (CLI with `--help`, JSON output, exit 0/1). See candidates in the "Detected Repetition" section of each `wiki/clusters/<id>.md`.
4. **contract** — verifiable `acceptance`, ideally with an `agent/tools/validate_*.py`.
5. **loop** — "Loop" section in `SKILL.md` (plan → execute → inspect → critique → correct → test, max 3 rounds).
6. **tested** — write the task in `evals/tarefas/<nome>-NN.md` and pass at least 2.
7. **approved** — real-world use without corrections. If a correction was needed: add a line to `FALHAS.md` + update the skill.

Mark each step in the interface (or edit `migracao.estagio` in the frontmatter). Skills
absorbed by another should be marked **discontinued**, with `destino` pointing to the skill that remains.

### 5. Maintain the wiki (LLM wiki style)

```bash
cp fonte.md wiki/raw/2026-09-20-fonte.md   # raw source: date in filename, never edit
# the agent consolidates into wiki/conceitos/ (sources, generated, related), regenerates index.md and writes to log.md
python3 tools/wiki_lint.py
```

Complete frontmatter, actor, and operation conventions are in `wiki/SCHEMA.md`.

### 6. Use the base agent

`agent/instructions.md` is the always-on prompt for the generalist agent (cycle + router
intent → cluster → skill). To use it in Claude Code, paste it into the `CLAUDE.md` of the project where
the agent will operate, or point to it; `agent/agent.yaml` stores the model, routing
policy, and loop limit.

## Migration state lives in the wiki

Each skill has **one page** in `wiki/skills/<nome>.md`. The migration stage
is in that page's frontmatter (the `migracao:` field), which the interface reads and
writes. There is no parallel `state.json`: the wiki is the single source of truth.

Stages (the plan's 9 practical strategy steps, condensed):

`inventariado → mapeado → skill → tools → contrato → loop → testado → aprovado` (or `descontinuado`)

## Pilots

The plan says to start with 3 agents. The pilot contracts are in `migracao/contratos/`:

- **reels** → cluster `reels` (`reel-edita-inema`, `reel-edita-inematds`, `forja-reel`, `roteirista-inema`)
- **video-explicativo** → cluster `video-explicativo` (`video-explicativo`, `videoprodutor`, `faceless-explainer`)
- **curso** → cluster `curso` (`formato-curso-v5`, `formato-curso-v2`, `revisar-curso`, `videos-cursos-inema`)

`cria-books`, mentioned in the plan, does not exist as a local skill: it is recorded as a gap.
